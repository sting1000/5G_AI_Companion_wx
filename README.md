# 5G AI Companion（微信小程序 MVP）

面向空巢老人的 AI 语音陪伴小程序 MVP，核心闭环为：

`子女配置 -> 老人语音通话 -> 跨通话记忆 -> 通话摘要`

## 项目亮点

- 微信小程序原生实现，适老化、低学习成本
- 实时语音对话链路（WebSocket）
- 跨通话记忆（兴趣、事件、跟进项、称呼偏好等）
- 通话后结构化摘要（含情绪与提醒候选）
- 本地存储可用，云函数可平滑接入

## 技术栈

- 前端：微信小程序原生（WXML / WXSS / JS）
- 实时语音：豆包端到端实时语音 API
- 摘要生成：火山方舟 LLM API（云函数中调用）
- 数据层：微信云开发 CloudBase + 本地存储兜底

## 核心能力说明

### 1) 通话体验

- 通话连接分阶段提示（拨号、授权、连接、准备、接通）
- 来电接听态防重复操作与状态回馈
- 异常音色自动回退，提高可用性
- 播放器异常自愈与重试，增强稳定性

### 2) 对话安全边界

- 对“线下陪同/代办”等越界表述进行检测
- 越界时触发安全改写与温和拒绝策略
- 固定可执行建议：联系家属 / 120 / 社区服务

### 3) 记忆与提醒

- 记忆条目评分与冷却机制，降低重复提及
- 支持“叫我 XXX”称呼偏好提取与持久化
- 从摘要结果与用户原话中提取提醒候选
- 高置信提醒自动入库，避免重复创建

## 快速开始

### 1. 环境准备

- 安装微信开发者工具
- 开通并启用微信云开发（CloudBase）
- 准备豆包语音 API 凭证与方舟 API Key

### 2. 本地配置

在 `miniprogram/` 下复制配置模板：

```bash
cp miniprogram/config.local.example.js miniprogram/config.local.js
```

填写真实凭证（`config.local.js` 已被忽略，不会提交）：

- `speech.appId`
- `speech.accessKey`
- `ark.apiKey`

### 3. 云函数配置（可选但推荐）

进入微信开发者工具后：

1. 上传并部署 `cloudfunctions/generateSummary`
2. 为云函数配置环境变量 `ARK_API_KEY`

说明：

- 若未配置 `ARK_API_KEY`，项目仍可运行，将回退到本地规则摘要
- 配置后可得到更好的结构化摘要结果

### 4. 运行项目

1. 用微信开发者工具打开仓库根目录
2. 等待小程序与云函数构建完成
3. 编译并预览页面流程：
   - `onboarding` 配置老人信息
   - `call` 发起/接听语音通话
   - `summary` 查看摘要与关键信息

## 开发建议

- 每次改动后先在微信开发者工具编译验证
- 涉及实时语音链路改动时，务必做真机连通性测试
- 不要在日志里打印凭证信息
- 提交信息统一使用英文（如 `feat: ...` / `fix: ...`）

## 常见问题

### Q1: 为什么没有方舟 Key 也能看到摘要？

项目内置了本地规则摘要 fallback，用于保证演示链路可用。

### Q2: 提醒是如何生成的？

提醒候选来自两路：

- 云函数结构化摘要返回的 `reminderCandidates`
- 通话中用户原话的本地规则提取

并通过置信度阈值去重后写入提醒池。

### Q3: 记忆为什么不会每次都重复问同一个点？

记忆模块引入了使用记录、分类型预算、冷却窗口和评分排序，优先召回更“新鲜且有价值”的信息。
