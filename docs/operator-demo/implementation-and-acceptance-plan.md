# iOS + 独立云端 Demo 实施与验收计划

> 目标：交付一条可在真机稳定复演的“语音创建 → 云端理解与保存 → 本地通知 → 完成/稍后 → 子女查看”闭环。  
> 本计划不承诺 App Store 发布、运营商远程推送或 1000 人生产能力。

## 1. 成功标准

只有同时满足以下四个准入门槛，iOS 才进入客户主演示：

1. App 可在演示 iPhone 安装、启动并完成通知/麦克风权限流程；
2. 10 条核心语音测试中，预期可自动处理的语句全部得到正确结构化结果；
3. App 退到后台或锁屏后，本地通知按演示时间出现；
4. App 重启并重新拉取后，提醒及处理状态与云端一致。

任一门槛未通过，使用小程序 + App 高保真原型 + 已验收录屏的备用方案。

## 2. 明确范围

### 必须实现

- 同一 iOS App 支持老人和子女两个预置演示账号；
- 老人端：今日事项、语音录制、解析确认、提醒列表；
- 云端：ASR、结构化意图、提醒 CRUD、状态事件、最小鉴权；
- 本地通知：单次、每日、每周；
- 处理动作：已完成、稍后 10 分钟；
- 子女端：提醒状态、未确认升级和一周聚合；
- 演示模式：明确标注的身份切换和时间压缩；
- 演示样例数据与真实运行数据明确区分。

### 本轮不实现

- 微信与 iOS 实时同步；
- 子女跨设备创建后自动触达老人；
- APNs 或运营商远程推送；
- 手机号验证码、真实家庭绑定、多家庭管理；
- App Store、TestFlight 外部测试或客户自行安装；
- 1000 人容量、SLA、容灾和 7×24 运维；
- 自由陪聊、长期记忆、医疗判断和紧急救援；
- 公众号、企业微信和电话外呼。

## 3. 总体架构

```text
┌──────────────────────── iOS SwiftUI ────────────────────────┐
│ 老人首页 │ 录音 │ 解析确认 │ 提醒详情 │ 子女首页 │ 演示身份切换 │
│                         │                                   │
│ Keychain Token │ 本地缓存 │ UNUserNotificationCenter       │
└─────────────────────────┼───────────────────────────────────┘
                          │ HTTPS / JSON + 短音频
┌─────────────────────────▼───────────────────────────────────┐
│ 独立 FastAPI 服务                                            │
│ 鉴权 │ ASR 编排 │ 意图结构化 │ 提醒服务 │ 家庭聚合 │ 健康检查 │
└───────────────┬───────────────────┬─────────────────────────┘
                │                   │
       阿里云百炼 ASR / LLM     独立 PostgreSQL
```

### 依赖边界

- 不修改 K12 代码、数据库、租户或部署；
- 可借鉴 K12 的 FastAPI 分层、配置、超时重试和迁移组织；
- iOS 安装包不保存阿里云 API Key 或数据库凭证；
- 新服务使用独立数据库或至少独立数据库名与账号；
- 所有公网调用必须使用 HTTPS。

## 4. 最小 API 契约

### `POST /v1/auth/demo-login`

输入：演示账号和密码。  
输出：短期访问 Token、用户角色、家庭 ID、演示数据标识。

### `POST /v1/reminders/parse`

输入：不超过 30 秒的短音频、设备时区、当前时间和幂等请求 ID。服务端限制文件大小与允许的音频格式。  
处理：ASR → 结构化意图 → Pydantic 校验。  
输出：

```json
{
  "transcript": "下周三早上九点提醒我去医院复诊",
  "draft": {
    "title": "去医院复诊",
    "scheduledAt": "2026-09-09T09:00:00+08:00",
    "timezone": "Asia/Shanghai",
    "recurrence": { "type": "once" },
    "confidence": 0.95,
    "needsConfirmation": false,
    "missingFields": []
  }
}
```

约束：此接口只返回草稿，不保存提醒。

### `POST /v1/reminders`

输入：用户确认后的标题、时间、时区和重复规则。  
输出：服务端提醒 ID、版本号和规范化后的下一次触发时间。

### `GET /v1/reminders`

按登录用户和家庭关系返回有权限查看的提醒，不接受客户端自行指定任意用户 ID。

### `PATCH /v1/reminders/{id}/status`

允许状态变更：`scheduled → completed`、`scheduled → snoozed`、`snoozed → completed`。服务端校验权限与状态迁移。

### `GET /v1/families/me/weekly-summary`

返回由提醒事件聚合得到的计数和趋势。自然语言摘要只能基于这些确定数据生成。

### `GET /healthz`

只表示进程存活。另提供内部 readiness 检查，覆盖数据库和必要外部模型依赖；不得用单一 200 响应代表完整业务可用。

## 5. 最小数据模型

### User

- `id`
- `display_name`
- `role`: `elder | child`
- `family_id`
- `is_demo`

### Reminder

- `id`
- `family_id`
- `elder_user_id`
- `created_by_user_id`
- `title`
- `scheduled_at_utc`
- `timezone`
- `recurrence_type`: `once | daily | weekly`
- `recurrence_payload`
- `status`: `scheduled | snoozed | completed | unconfirmed | escalated`
- `version`
- `created_at` / `updated_at`

### ReminderEvent

- `id`
- `reminder_id`
- `event_type`: `created | scheduled_local | snoozed | completed | unconfirmed | escalated`
- `actor_user_id`
- `occurred_at`
- `metadata`

说明：`unconfirmed` 只表示超过约定时间没有完成确认，不代表通知已送达，也不代表老人不安全。

## 6. 意图解析规则

### 自动推断

- 明确日期 + 明确时间；
- 相对日期 + 明确时间；
- “周三八点”等可解释为最近未来时点的表达；
- “晚上八点”等明确时间段。

### 必须追问

- 没有具体时间；
- “晚点、过会儿、有空”等模糊表达；
- 每日多次但没有给出各次时间；
- 模型返回时间早于当前时间且无法合理滚动；
- 事项为空或同时包含多个冲突时间。

### 用户确认

- 确认页必须展示原始转写、事项、日期、时间和重复规则；
- 对 AM/PM 或最近时点的推断展示“已理解为……”；
- 用户可修改或取消；
- 确认前不写入 Reminder，也不设置通知。

### 演示时间压缩

- 原始 `scheduled_at` 始终保存用户确认的真实业务时间；
- “30 秒后出现通知”只由明确开启的本地演示模式映射；
- 演示触发时间不得回写成业务提醒时间，也不得出现在正式构建；
- 页面持续显示“演示时间已压缩”，避免客户将其理解为生产调度。

## 7. 同步与错误策略

- 服务端是提醒数据主源，App 只保留缓存和系统通知计划；
- `POST /reminders` 成功后才安排本地通知；
- 本地通知安排失败时显示失败，不显示完整成功状态；
- ASR 或意图失败时保留录音/文字草稿供当前会话重试，默认不长期保存原始录音；
- 所有创建和状态更新使用幂等请求 ID，避免重试产生重复提醒；
- App 拉取数据时使用版本号避免旧缓存覆盖新状态；
- Demo 不做复杂离线写入与冲突合并。

## 8. 实施顺序与阶段门

### Gate 0：开发环境

任务：

- 安全释放磁盘，使可用空间至少达到 60GB；
- 安装与当前 macOS 兼容的完整 Xcode 和一个 iOS Runtime；
- 创建最小 SwiftUI App；
- 在真机安装并显示 10 秒后的本地通知。

通过标准：真机录屏证明 App 退到后台或锁屏后出现通知。  
未通过：iOS 不进入主演示范围，使用 P2 备用方案。

### Gate 1：独立云端

任务：

- 建立独立 FastAPI 工程、配置和容器；
- 配置独立数据库、迁移、演示账号和 Token；
- 接入短音频 ASR 与结构化意图；
- 部署 HTTPS；
- 完成 API 契约测试。

通过标准：在不含 iOS 的情况下，用固定音频完成“解析草稿 → 确认创建 → 重新查询”。

### Gate 2：老人端真实闭环

任务：

- 完成首页、录音、处理中、确认、详情与通知；
- 支持单次、每日、每周；
- 支持已完成、稍后 10 分钟；
- 接入云端 Token、创建和状态更新。

通过标准：真机连续完成 10 次核心路径，无重复提醒、错时区或假成功。

### Gate 3：子女角色与商业展示

任务：

- 同一 App 内增加子女账号首页；
- 将明确标注的样例提醒事件写入独立后端，展示完成、稍后、未确认与升级状态；
- 展示一周聚合和三项建议动作；
- 演示样例数据有持续可见的标识。

通过标准：角色切换后服务端仍校验数据权限；子女不能通过修改请求参数读取其他家庭。

说明：本轮不建设后台定时任务和远程推送，`unconfirmed` 与 `escalated` 使用预置演示事件展示产品逻辑，不声称系统已能在两台设备之间自动升级通知。

### Gate 4：演示验收

任务：

- 按正式脚本完成三次无中断彩排；
- 在演示网络和备用热点各完成一次；
- 生成同版本、同数据、同流程的备用录屏；
- 冻结构建和演示数据；
- 完成对外话术审查。

通过标准：四个准入门槛全部通过，公司负责人、产品经理和技术负责人共同 Go。
