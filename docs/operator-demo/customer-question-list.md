# 运营商客户问题清单

> 目标：确认最终产品载体、接口与责任边界，为联合方案评估获取足够输入。  
> 使用方式：会上优先问 P0；无法当场回答的项目记录负责人和补充日期。

## P0：没有答案就不能承诺方案

### 1. 产品入口与用户旅程

1. 最终入口优先考虑现有运营商 App、独立 App、微信平台，还是其他养老服务平台？
2. 老人和子女是否都使用同一个运营商 App？现有 App 是否已经区分家庭成员角色？
3. 首批目标用户使用的手机系统、常用 App 和网络条件如何？
4. 首批最希望解决的是服药、复诊、生活事项，还是运营商自有服务提醒？
5. 客户希望老人自己创建提醒，还是子女远程创建为主？

### 2. App 集成与推送

1. 现有 App 是原生 iOS/Android、跨端框架，还是 H5 容器？
2. 是否已有统一推送平台、消息中心和系统通知能力？
3. 是否能提供推送接口文档、测试环境、测试账号和送达回执？
4. 是否支持点击通知后按参数跳转到指定页面？
5. 通知权限关闭、推送失败、设备离线时，现有平台如何处理？
6. 我方预计以 API、SDK、H5 模块还是源码方式集成？最终由谁负责 App 发布？

### 3. 身份与家庭关系

1. 运营商 App 当前使用手机号、统一用户 ID 还是其他账户标识？
2. 是否已有家庭账户或亲情号关系，可以用于绑定老人和子女？
3. 老人与子女的数据授权由谁发起、如何确认、如何解绑？
4. 多个子女关注一位老人、一个子女管理多位老人是否属于首期范围？

### 4. 服务器与部署

1. 可提供服务器的 CPU、内存、磁盘、操作系统、网络区域和出口策略是什么？
2. 是否提供 GPU？客户期望模型 API 调用还是本地部署？
3. 是否允许 Docker；是否已有 Kubernetes、数据库、Redis、对象存储和网关？
4. 是否能提供公网或专网 HTTPS 域名、证书和防火墙配置？
5. 开发、测试、生产环境是否隔离？谁负责部署、监控、备份和故障响应？

### 5. 数据、安全与合规

1. 语音、转写文本、提醒和家庭关系分别允许保存多久？
2. 原始录音是否允许保存？本方案建议默认不长期保存。
3. 数据是否必须驻留运营商环境或指定地域？
4. 客户有哪些等保、审计、日志脱敏、密钥托管和漏洞扫描要求？
5. 老人授权、子女查看范围和撤回授权如何落地？
6. 是否禁止将数据用于模型训练？第三方模型调用需要哪些审批？

## P1：决定 PoC 范围与商业方案

### 6. 试点设计

1. 客户希望先验证多少名用户、持续多久、覆盖哪些城市或社区？
2. 试点用户由谁招募、培训和支持？
3. 试点期间谁处理用户反馈、账号问题和异常提醒？
4. 双方认可哪些验证指标？目标值何时共同制定？
5. PoC 结束后的扩展、暂停和退出条件是什么？

### 7. 商业与计费

1. 运营商倾向按用户、套餐、调用量还是收入分成计费？
2. ASR、LLM和推送成本由谁承担，如何设单用户预算上限？
3. 基础提醒、家庭关怀和 AI 陪伴是否适合分档销售？
4. 开发费、集成费、年度运维费和模型使用分成分别如何结算？
5. 用户投诉、退款、服务暂停和超额使用由谁负责？

## P2：规模化前确认

1. 1000 人是意向规模、PoC 后目标，还是已有预算与上线时间？
2. 峰值并发、每日提醒量、可接受延迟和可用性要求是什么？
3. 是否需要多租户、运营看板、审计导出和工单系统？
4. 是否要求双活、容灾、数据恢复目标和 7×24 支持？
5. 后续是否扩展到语音陪伴、健康设备或线下社区服务？
