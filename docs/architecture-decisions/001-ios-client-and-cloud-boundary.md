# 决策：iOS 轻客户端配合独立云端完成提醒闭环

## 背景与问题

运营商演示需要证明自然语音创建事项、云同步和系统提醒，同时保留未来接入运营商 App 的路径。密钥、模型调用和共享数据不能依赖单台手机，也不能进入客户端安装包。

## 候选方案

- A：全部放进 iOS App——实现快，但密钥暴露、没有可靠云同步，后续接入运营商 App 时需要重做。
- B：iOS 轻客户端 + 独立云端——客户端负责设备交互，云端负责共享能力；多一个服务，但边界清楚。
- C：Lovable PWA + 云端——页面原型快，但系统通知和原生安装仍需额外封装与 Xcode。

## 决策

选择 B。iOS 负责录音、界面、结果确认和本地通知；云端负责鉴权、保管密钥、调用语音/意图 API、保存提醒并返回结构化结果。

## 为什么（用户复述）

“iOS 客户端负责录音、界面、确认和本地通知，云端参考 K12 项目，有 API 等相关组件，进行保管密钥、调用语音/意图 API、保存提醒并返回结构化结果。”

补充：本地通知用于本轮 Demo 验证终端体验；正式接入运营商 App 后，跨设备创建和后台触达仍需要运营商推送能力。

## 可迁移原理

凡是涉及共享状态、服务端密钥或多客户端复用的能力应放在云端；只与当前设备交互直接相关的能力留在客户端。
