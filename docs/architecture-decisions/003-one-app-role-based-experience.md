# 决策：同一 App 按云端角色呈现老人端和子女端

## 背景与问题

产品需要同时覆盖老人创建与处理提醒、子女查看状态与接收关怀升级，但不希望维护两个独立 App。角色差异不能只靠前端页面开关，否则无法形成真实的数据权限边界。

## 候选方案

- A：老人端和子女端分别开发——权限直观，但研发、发布和维护成本更高。
- B：同一 App、独立账号、云端角色与家庭关系——共享能力和数据模型，但需要服务端鉴权与授权。
- C：同一账号随意切换角色——演示方便，但不能代表正式产品的权限模型。

## 决策

选择 B。Demo 使用两个预置账号，并提供明确标注的“切换演示身份”；正式产品由云端账号角色和家庭关系决定页面与数据权限。

## 为什么（用户复述）

“不用一个新的端，只用同一个 App 的不同用户类型进行分辨。”

补充：复用同一个客户端可以减少重复开发并保持体验一致；由于角色决定可见家庭数据，演示身份切换只能代表两个预置账号，正式权限必须由云端校验，不能信任客户端开关。

## 可迁移原理

当角色决定可见数据或可执行操作时，客户端只负责呈现，最终授权必须由服务端校验。
